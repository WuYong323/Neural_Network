## Week 1 · 循环神经网络(Recurrent Neural Networks)

> **本周地图**:为什么需要序列模型 → RNN 结构与参数共享 → BPTT → 5 种输入输出结构 → 语言模型与采样 → 梯度消失全景 → GRU/LSTM(引用演进笔记)→ BRNN/Deep RNN。

### 1.1 为什么需要"专门的"序列模型 + 符号约定

**问题背景**:普通全连接网络 / CNN 处理"一张图、一条固定长度向量"很行,但序列数据有两个它们搞不定的特点:

1. **变长**:句子有长有短,标准网络的输入维度是**写死**的。
2. **顺序有意义 + 位置间共享规律**:"我 昨天 吃了 苹果" 和 "苹果 吃了 昨天 我" 完全不同;而"识别人名"这个规律,无论人名出现在句首还是句尾都该适用。

**类比**:标准网络像一台**只能装固定尺寸零件的冲压机**,来一个变长的东西就傻眼。RNN 像一条**流水线上的同一个工人**——不管来多少个零件,他用**同一套手艺(同一套参数)**一个接一个处理,并且把"上一个零件的处理心得(hidden state)"带到下一个。

**符号约定(Ng 的记法,后面全课都用)**:
- 一个序列样本 x 有 Tx 个时间步,第 t 步记 `x<t>`;输出序列有 Ty 个,第 t 个记 `y<t>`。
- 第 i 个训练样本的第 t 步:`x(i)<t>`。
- 词用 **one-hot 向量**表示:先建一个词表(vocabulary,比如 10000 词),`x<t>` 是一个 10000 维、只有对应词那一位是 1、其余全 0 的向量。(这个 one-hot 的种种毛病,正是 Week 2 词嵌入要修的,记住这个坑。)

### 1.2 RNN 结构 + 前向 + 参数共享(原理+直觉)

**是什么**:RNN 维护一个隐藏状态 `a<t>`(activation,也叫 hidden state),逐步更新:

```
a<t> = tanh( Waa · a<t-1> + Wax · x<t> + ba )      # 携带历史 + 吃新输入
ŷ<t> = softmax( Wya · a<t> + by )                  # 从当前状态给出预测
```

**三个直觉要点**:

- **`a<t>` 是"到目前为止的记忆摘要"**:它同时装着"历史 `a<t-1>` 的贡献"和"当前输入 `x<t>` 的贡献",tanh 把值压回 (−1,1) 防止逐步累积爆炸。→ 这个"固定大小向量装全部历史 = 有损压缩"的本质,演进笔记 §2.1 用"传话游戏"讲透了,这里不重复。
- **参数共享是灵魂**:注意 `Waa, Wax, Wya` **在每个时间步都是同一套**,不随 t 变。这一步回答了开篇第 1 题:
  - 它让模型能处理**任意长度**——多来几步就多用几次同一套 W,参数量不随序列变长而增加;
  - 它让"某个规律(比如识别人名)"**在任何位置都能复用**,不用在每个位置重新学一遍。若不共享,第 100 个位置的知识对第 101 个位置毫无帮助,且长序列参数量爆炸、根本没法训。
- **单向 RNN 的局限**:`a<t>` 只看到了 `x<1..t>`(过去),看不到未来。判断 "Teddy" 是不是人名,可能需要看后面是 "bear"(泰迪熊)还是 "Roosevelt"(总统)——单向 RNN 做不到。这个坑由 1.8 的 BRNN 来填。

### 1.3 可运行代码:手写一个 RNN 前向,看清"参数共享 + 逐步携带"

```python
# 环境: python>=3.9, numpy. 运行: python rnn_forward.py
# 目的: 不依赖框架, 手算一遍 RNN 前向, 亲眼确认"每步复用同一套 W"
import numpy as np

np.random.seed(0)
Tx, n_x, n_a, n_y = 4, 3, 5, 2      # 4 个时间步, 输入 3 维, 隐藏 5 维, 输出 2 维

# ★ 全程只有这一套参数, 4 个时间步反复用它 —— 这就是"参数共享"
Wax = np.random.randn(n_a, n_x) * 0.1
Waa = np.random.randn(n_a, n_a) * 0.1
Wya = np.random.randn(n_y, n_a) * 0.1
ba, by = np.zeros((n_a, 1)), np.zeros((n_y, 1))

def softmax(z): e = np.exp(z - z.max(0)); return e / e.sum(0)

xs = np.random.randn(n_x, Tx)        # 4 步输入
a_prev = np.zeros((n_a, 1))          # a<0> 全零
for t in range(Tx):
    x_t = xs[:, t:t+1]
    a_prev = np.tanh(Waa @ a_prev + Wax @ x_t + ba)   # 复用同一套 W
    y_hat = softmax(Wya @ a_prev + by)
    print(f"t={t}  a<t> 前2维={a_prev[:2,0].round(3)}  ŷ<t>={y_hat[:,0].round(3)}")
# 预期: 打印 4 行, 每行 a<t> 都不同(因为携带了历史), 但用的是同一套 Waa/Wax
```

**看点**:循环体里的 `Waa @ a_prev + Wax @ x_t` 每轮都用**同一个** `Waa/Wax`。这既是 RNN 能力的来源(共享→泛化到任意长度),也是它痛苦的来源——同一个 `Waa` 被连乘 Tx 次,这为 1.6 的梯度消失/爆炸埋下伏笔(同一个矩阵连乘,特征值 <1 就指数衰减,>1 就指数爆炸)。

### 1.4 BPTT:时间反向传播(演进笔记没讲,补上)

**是什么**:RNN 的反向传播叫 **BPTT(Backpropagation Through Time,时间反向传播)**。核心思想:把 RNN 沿时间"**展开(unroll)**"成一个很深的普通网络——Tx 个时间步就相当于 Tx 层,只不过每层共享同一套 W——然后照常反向传播。

**类比**:BPTT 就像**复盘一条流水线的责任追溯**。最终产品出了问题(loss),你要沿流水线**倒着**一站一站追:第 t 站的失误,既来自它自己,也来自它从第 t−1 站接过来的半成品。因为每一站是**同一个工人(共享 W)**,所以最后要把**所有站追溯到的"这个工人该改进多少"加总**,才是对 W 的一次更新。

**关键公式直觉**(不用背,理解"为什么梯度会连乘"):对 `Waa` 的梯度,要沿时间链式法则累加,链条里反复出现 `∂a<t>/∂a<t-1> = Waa · diag(tanh')`。展开 k 步就会出现 **`Waa` 的 k 次幂**——这就是梯度消失/爆炸的数学根源(1.6 详谈)。

**工程细节:Truncated BPTT(截断 BPTT)**。序列几千步时,完整展开占显存、算得慢。工业上用**截断**:只沿最近 k 步(如 k=128)回传梯度,更早的截断掉。这是"**用一点长依赖的精度,换显存和速度**"的经典权衡——和你在演进笔记 §6 见到的"时间 vs 空间"权衡是同一种工程思维。

### 1.5 RNN 的 5 种输入输出结构(Tx 和 Ty 不一定相等)

Ng 这节把 RNN 能干的活按"输入长度 : 输出长度"分类,这是理解后面 Seq2Seq 的地基:

| 结构 | Tx : Ty | 典型任务 | 直觉 |
|---|---|---|---|
| **one-to-one** | 1:1 | 普通分类(其实退化成标准网络) | 没用到循环 |
| **one-to-many** | 1:多 | **音乐/文本生成**:给个开头,吐一整段 | 一个种子长出一串 |
| **many-to-one** | 多:1 | **情感分类**:读完整句,输出一个情感分 | 读完再表态 |
| **many-to-many(Tx=Ty)** | n:n | **命名实体识别**:每个词标一个标签 | 逐词对齐输出 |
| **many-to-many(Tx≠Ty)** | n:m | **机器翻译**:读完源语言,再生成目标语言 | 先读后写,长度可不等 |

**为什么这个分类重要**:最后一种(Tx≠Ty 的多对多)天然就是 **Encoder-Decoder** 结构——先用一个 RNN 把源句"读成一个摘要向量",再用另一个 RNN 从这个摘要"写出译文"。**这正是 Week 3 Seq2Seq 的原型**,记住这个伏笔。

### 1.6 语言模型与序列采样:让 RNN "自己写句子"

**语言模型(language model)是什么**:给一个句子,估计它出现的概率 P(sentence)=P(y<1>)·P(y<2>|y<1>)·P(y<3>|y<1>,y<2>)·…。RNN 做法:每个时间步的输出 `ŷ<t>` 是"**给定前面所有词,下一个词是词表中每个词的概率分布**"(softmax),训练时用真实的下一个词做标签(这叫 **teacher forcing**,把真实的 `y<t>` 喂给下一步而不是喂模型自己的预测)。

**采样生成(sampling novel sequences)——one-to-many 的实战**:训练好后,让它自己写:
1. 从 `ŷ<1>` 这个分布里**随机采样**一个词(不是取 argmax!取 argmax 会让输出僵化重复);
2. 把采样到的词当作下一步的输入 `x<2>`;
3. 重复,直到采样到句末标记 `<EOS>`。

**类比**:teacher forcing 训练像**跟着字帖描红**(每一步都有正确答案兜底);采样生成像**放手自己写作文**(上一个字写成啥,下一个就基于啥继续)。这个"训练时看真值、推理时看自己上一步输出"的差异,叫 **exposure bias(暴露偏差)**,是 Seq2Seq 一个经典难题。

> **工业锚点(直连你的主线)**:这里的"逐词采样、把上一步输出拼回去当下一步输入"**就是自回归生成(autoregressive decoding)**——和你在 W6 亲手实现的 LLM decode 循环是**同一个东西**。GPT 本质上就是一个巨大的 RNN 语言模型的"精神后继":同样是 P(下一个词 | 前文),只是把 RNN 换成了 Transformer。而"每步只产 1 个新 token、却要重跑一遍"带来的重复计算,正是 KV Cache 存在的理由 → 见演进笔记 §5.2。**Week 1 的语言模型 = LLM 的思想源头**,这条线你要能一口气讲通。

### 1.7 梯度消失/爆炸的完整全景(开篇第 2 题的题眼)

演进笔记 §3.1 讲了 LSTM 门控"为什么能缓解长依赖",但**没讲清楚消失和爆炸是两个不同的病**。这里补全:

**共同根源**:1.4 说过,BPTT 的梯度里反复出现 `Waa` 的连乘。设其主特征值为 λ:
- **λ < 1**:连乘 k 次 → λ^k → 0,**梯度消失(vanishing)**。表现:**远处的梯度传不回来**,模型学不到长依赖(句首的信息影响不了句尾的预测)。这是**沉默的病**——loss 还在降,但长依赖就是学不会,不报错、难发现。
- **λ > 1**:连乘 k 次 → λ^k → ∞,**梯度爆炸(exploding)**。表现:梯度变 NaN、loss 突然飞掉。这是**吵闹的病**——一眼能看见。

**两个病,两套解法(这是关键区别)**:

| | 梯度消失 | 梯度爆炸 |
|---|---|---|
| 表现 | 长依赖学不会,但不报错 | loss 变 NaN,训练崩 |
| 好不好发现 | 难(沉默) | 易(明显) |
| 解法 | **门控结构**(GRU/LSTM):给记忆开一条"加法高速路",梯度沿 cell state 近似 =1 地流,不被连乘挤压 → 见演进笔记 §3.2 的 `c=f*c_prev+i*g` 公式 | **梯度裁剪(gradient clipping)**:梯度范数超过阈值就等比缩回。简单粗暴但极有效 |

**为什么门控治消失、治不了爆炸**:门控是改**结构**,让梯度有条不衰减的通路;但它管不住某次更新里梯度**数值**恰好炸大——那得靠裁剪这种**数值层面**的急救。所以工业上 RNN 训练**两个都用**:结构上用 LSTM,数值上叠 gradient clipping。

> **工业锚点**:梯度爆炸/消失不是 RNN 专利。深层 Transformer 训练同样面临数值稳定问题,解法演化成了 **残差连接(residual,让梯度走捷径,思想和 cell state 高速路一脉相承)+ LayerNorm + 学习率 warmup + 混合精度下的 loss scaling**。你以后调大模型训练看到的 "loss spike""grad norm 监控",根子就在这一节。

### 1.8 GRU / LSTM / BRNN / Deep RNN(快速过 + 引用)

- **GRU / LSTM**:门控如何缓解长依赖、cell state 的"乘+加"梯度高速路、四门合并成一个大矩阵乘的算子融合雏形 —— 演进笔记 §3 已深讲,**这里不重复**,只强调一句本课要点:**LSTM 有 3 个门(遗忘/输入/输出)+ 独立 cell state,GRU 精简成 2 个门(更新/重置)、把 c 和 a 合并**。没有谁绝对更好:GRU 更轻更快、LSTM 更强更稳,实践中都试。

- **双向 RNN(BRNN,Bidirectional RNN)**:填 1.2 那个"看不到未来"的坑。做法:跑两个 RNN,一个从左到右(`→a<t>`)、一个从右到左(`←a<t>`),把两个方向的状态**拼起来**再做预测。这样每个位置都同时看到了**过去和未来**的上下文。
  - **代价与工业锚点**:BRNN 必须**拿到完整序列**才能算(反向那条 RNN 要从最后一个词起步),所以**不能做流式/实时**(比如实时语音转写就没法用纯 BRNN,得等你说完)。这个"需要全序列 vs 实时"的矛盾,在流式 LLM 服务里对应"要不要等 prompt 收全"的工程决策。

- **深层 RNN(Deep RNN)**:把 RNN 堆几层(上一层每个时间步的输出,当下一层的输入)。因为时间维已经很"深"了,RNN 一般堆 2~3 层就够(不像 CNN 动辄上百层)。

### Week 1 小结(一句话)

> RNN 靠**参数共享**处理变长序列、靠 **hidden state** 逐步携带历史(有损压缩),训练靠 **BPTT**;但同一个 `Waa` 连乘导致**梯度消失(门控治)/爆炸(裁剪治)**;它能做生成(one-to-many 采样,LLM 自回归的祖师爷)、分类(many-to-one)、翻译(Tx≠Ty,Seq2Seq 原型)。**串行的枷锁**贯穿始终 → 见演进笔记 §2。

## Week 2 · 自然语言处理与词嵌入(Word Embeddings)

> **本周地图**(演进笔记完全没讲,本周是纯增量):one-hot 的困境 → 特征化嵌入 → 嵌入矩阵与迁移学习 → 类比推理与余弦相似度 → Word2Vec(skip-gram)→ 负采样 → GloVe → 情感分类 → 词嵌入去偏。
>
> **一句话主线**:Week 1 我们用 **one-hot** 表示词,那是个"每个词互相垂直、毫无关系"的烂表示。整个 Week 2 就在干一件事:**把词从 one-hot(稀疏、无语义)换成 embedding(稠密、含语义)**,并讲清这些语义向量怎么学出来。

### 2.1 词的表示:one-hot 的三宗罪 → 特征化嵌入(开篇第 3 题题眼)

**one-hot 的问题**:词表 10000 词,"苹果 Apple"是第 4321 位为 1 的向量,"橙子 Orange"是第 6257 位为 1。它们的**内积 = 0,余弦相似度 = 0**——数学上"苹果"和"橙子"跟"苹果"和"坦克"一样毫无关系。三宗罪:

1. **零泛化**:模型学会了"我想喝一杯**橙**汁",遇到"我想喝一杯**苹果**汁"却当全新的东西——因为两个词向量正交,知识传不过去。
2. **维度灾难 + 稀疏**:10000 维里 9999 个 0,又大又没信息。
3. **无语义结构**:向量间距离不反映任何含义。

**类比**:one-hot 像给每个词发一个**纯数字工号**(4321 号、6257 号)——工号之间看不出谁和谁是同部门。**词嵌入(word embedding)** 像给每个词填一张**能力画像表**:是不是食物?是不是水果?甜不甜?于是"苹果"和"橙子"的画像高度相似(都是甜的水果),模型一眼看出它们是一类。

**特征化表示(featurized representation)**:给每个词一个稠密向量(比如 300 维),每一维**软性地**代表某种语义特征(性别、年龄、食物性、抽象度…,实际学出来的维度不可解释,但整体编码了语义)。这样"苹果"和"橙子"向量很近,知识能互相迁移。

**可视化直觉**:把 300 维用 t-SNE 降到 2 维画出来,会看到**语义相近的词聚成团**——水果一堆、国家一堆、数字一堆。这就是嵌入"有语义结构"的肉眼证据。

### 2.2 嵌入矩阵 + 迁移学习(embedding 到底怎么"取")

**嵌入矩阵 E**:形状 `(嵌入维度 300, 词表大小 10000)`。第 j 列就是词表第 j 个词的 300 维嵌入向量。

**取一个词的嵌入 = 矩阵乘 one-hot**:`e_j = E · o_j`(o_j 是该词的 one-hot)。但这个矩阵乘**极其浪费**——本质就是"取出第 j 列",却要做一次 300×10000 的乘法(乘一堆 0)。

> **工业锚点(直连 LLM 实现)**:所以真实系统里**从不真的做这个矩阵乘**,而是用 **embedding lookup(查表)**——直接按索引 j 取第 j 行,O(1)。PyTorch 的 `nn.Embedding` 就是这么干的。这是你写任何 LLM 都会碰到的第一层:`token_ids → embedding table 查表 → 稠密向量`。词表大小 × 嵌入维度 = embedding 参数量,在大模型里能占到总参数的可观比例(比如词表 15 万 × 隐藏维 4096 ≈ 6 亿参数,光输入层)。而且很多模型把**输入 embedding 和输出 softmax 的权重绑定(weight tying)** 来省这一大坨参数——这又是"空间/参数量"权衡,和你 AI Infra 的关注点一脉相承。

**迁移学习(transfer learning)——词嵌入最实用的用法**:
1. 在**海量无标注文本**(几十亿词,网上随便爬)上预训练词嵌入(或直接下载别人训好的:Word2Vec/GloVe);
2. 迁移到你的**小数据任务**(比如只有 1 万条标注的命名实体识别);
3. 可选:在小数据上微调。

**为什么有效**:小任务里没见过的词(比如训练集里没"榴莲",但测试集有),因为预训练嵌入里"榴莲"和"苹果"很近,模型能**举一反三**。这正是 2.1 说的"零泛化"问题被彻底治好。→ 这套"大数据预训练表示 + 小数据迁移"的范式,就是后来 **BERT/GPT 预训练-微调**的思想胚胎。

### 2.3 词嵌入的性质:类比推理与余弦相似度

**惊艳的发现**:好的词嵌入能做**类比推理**。经典例子:

```
e(man) - e(woman) ≈ e(king) - e(queen)
```

即"男→女"的向量差,和"国王→王后"的向量差方向几乎一致。于是可以**做向量算术回答类比题**:"man 之于 woman,相当于 king 之于 ?"

```
answer = argmax_w  cosine( e(king) - e(man) + e(woman),  e(w) )
```

算出来 w = queen。**直觉**:`e(king) - e(man)` 抽出了"王权"这个方向,加上 `e(woman)` 就得到"女性的王权"≈ queen。

**为什么用余弦相似度(cosine similarity)而不是欧氏距离**:

```
cos(u, v) = (u · v) / (‖u‖ ‖v‖)
```

它衡量的是**两个向量的夹角(方向)**,不受长度影响。语义在嵌入里主要编码在**方向**上(高频词向量往往更长,但和语义无关),所以看方向比看距离更靠谱。类比:判断两个人"三观合不合",看的是**价值取向的方向**,不是他俩嗓门大小(向量长度)。

### 2.4 Word2Vec(skip-gram):嵌入怎么"无监督"学出来

**核心思想(一句话)**:"**一个词的含义,由它周围经常出现的词决定**"(distributional hypothesis,分布假说)。你告诉我"____"周围常出现"喝、汁、甜、树",我就知道空里大概是"苹果/橙子"这类。

**Skip-gram 任务设计**:随机取一个**中心词(center)**,让模型预测它**上下文窗口内(context)** 的词。比如句子 "I want a glass of orange juice",取中心词 "orange",让模型预测周围的 "glass / of / juice"。

```
中心词 c → 查嵌入 e_c → softmax over 全词表 → 预测上下文词 t 的概率
P(t | c) = exp(θ_t · e_c) / Σ_{j in vocab} exp(θ_j · e_c)
```

训练完,`E` 的每一列(每个词的 e_c)就是我们要的嵌入。**注意精妙之处**:我们根本不在乎"预测上下文"这个任务本身准不准——它只是个**借口任务(pretext task)**,真正的产物是训练过程中被逼着学好的**嵌入 E**。这种"用一个假任务逼出好表示"的套路,就是**自监督学习(self-supervised learning)** 的雏形——BERT 的"完形填空"、GPT 的"预测下一个词",全是这个思想。

**致命瓶颈(开篇第 4 题题眼)**:那个 softmax 的分母要**对全词表几万个词求和**,每算一步、每个训练样本都要遍历整个词表——慢到无法接受。这就引出负采样。

### 2.5 负采样(Negative Sampling):把"几万类 softmax"变成"廉价二分类"

**天才转化**:与其问"给定 orange,下一个词是词表里哪一个(几万选一的 softmax)",不如改问一堆**是非题**:

- (orange, juice) → 这俩是真实的上下文对吗?**是(1)** ← 正样本
- (orange, king) → 是吗?**否(0)** ← 负样本(随机采的)
- (orange, book) → 否(0)
- (orange, the) → 否(0)
- (orange, of) → 否(0)

每个正样本,配 **k 个随机采的负样本**(小数据集 k=5~20,大数据集 k=2~5)。于是原来"一个几万类的 softmax",变成 **k+1 个独立的逻辑回归(logistic regression)二分类**:

```
P(y=1 | c, t) = σ(θ_t · e_c)          # sigmoid, 只算 k+1 个词, 不再遍历全词表
```

**为什么这样又快又对**:
- **快**:每步只更新 k+1 个词向量,而不是几万个 → 计算量从 O(词表) 降到 O(k),天壤之别。
- **对**:数学上可证明,负采样是在近似原来的 softmax 目标。

**负样本怎么采(一个工程细节)**:不按词频均匀采(那样"the/of"这种高频词老被采),也不完全按频率(那样罕见词永远采不到),而是按 **词频的 3/4 次方** 采:`P(w) ∝ freq(w)^0.75`。这个 0.75 是**经验魔数**,在"照顾高频"和"不埋没低频"之间取了个甜点。

> **类比**:原来的 softmax 像**全班几万人排队,每次考试都要和所有人比个高下排名**(累死);负采样像**只和真同桌(正样本)+ 随机抽的几个人(负样本)两两 PK**,PK 谁更该是"上下文"。工作量骤降,效果却几乎一样。这种"**把昂贵的全局归一化,换成廉价的局部采样对比**"的思想,在对比学习(contrastive learning)、推荐系统召回里反复出现——是个通用大杀器。

### 2.6 GloVe:换个角度,直接拟合"共现统计"

**Word2Vec 是"预测式"(逐个样本预测上下文)**;**GloVe(Global Vectors)是"统计式"**——它先在整个语料上统计一张**共现矩阵 X**(X_ij = 词 i 和词 j 在窗口内共同出现的次数),然后直接拟合:

```
minimize  Σ_ij  f(X_ij) · (θ_i · e_j + b_i + b_j' − log X_ij)²
```

**直觉**:让"两个词向量的内积"去逼近"它们共现次数的对数"。共现越多的词对,内积越大 → 向量越近。`f(X_ij)` 是个权重函数,压制"the/of"这种超高频共现的过度影响。

**Word2Vec vs GloVe 一句话**:一个**流式地一对对学**(预测式,像刷题),一个**先汇总全局统计再一把拟合**(统计式,像先做好错题本再复习)。两者效果相当,GloVe 训练常更快、更容易并行(因为共现矩阵可以预先算好)。

### 2.7 应用:情感分类(sentiment classification)

**任务**:给一句评论,判断几星(1~5)。**难点**:标注数据少。**词嵌入的价值**:即使训练集里没出现过"absolutely delicious",预训练嵌入知道 delicious ≈ good,照样判对。

**两种做法,体现一个重要教训**:

- **朴素法**:把句子所有词的嵌入**平均**,再接 softmax。问题:**丢了词序**。"完全不好吃 not good" 会被"平均"成和"好吃 good"差不多(因为 not 的负面被稀释)。
- **RNN 法(many-to-one,呼应 1.5)**:把词嵌入序列喂进 RNN/LSTM,用最后的状态分类。**保留了词序**,能理解"not good"是负面。

> **教训**:这个对比精准复现了本课的核心张力——**"词袋(平均)丢顺序 vs 序列模型保顺序"**。它也解释了为什么 Transformer 明明抛弃了 RNN 的循环,却**必须**加位置编码(Week 4)——因为纯 attention 也是"集合操作、天然无序",不补位置信息就退化成高级词袋。这条线记住,Week 4 会收。

### 2.8 词嵌入去偏(debiasing):AI 伦理的第一课

**问题**:嵌入从人类语料里学,会**继承人类偏见**。比如 `e(man)-e(woman) ≈ e(programmer)-e(homemaker)`——嵌入"学会"了"男程序员/女家庭主妇"这种性别刻板印象。部署到简历筛选等场景会造成歧视。

**Ng 讲的去偏三步(直觉版)**:
1. **找出偏见方向**:用一批性别对(he-she, male-female…)的向量差,平均出一个"性别偏见轴"。
2. **中和(neutralize)**:对那些**本不该有性别的词**(doctor, nurse, programmer),把它们在"偏见轴"上的分量**投影掉**(拉到与偏见轴垂直)。
3. **均衡(equalize)**:对**本就成对**的词(grandfather-grandmother),调整到关于"中性平面"对称,使它们到 doctor 等中性词的距离相等。

> **工业锚点**:这是你会在**负责任 AI(Responsible AI)/ 大模型对齐**里反复碰到的议题的源头。现代 LLM 的偏见问题更复杂(藏在几百亿参数里,不是几个方向能投影掉的),靠的是 RLHF、数据清洗、红队测试。但"**表示里会悄悄编码社会偏见,且必须主动干预**"这个认知,从这节的词嵌入去偏就开始了。

### Week 2 小结(一句话)

> 把词从 **one-hot(正交、无语义、零泛化)** 换成 **embedding(稠密、含语义、可迁移、能做类比算术)**;嵌入靠"**由上下文定义含义**"的自监督任务学出来——Word2Vec 用**预测式 skip-gram + 负采样**(把几万类 softmax 降为廉价二分类),GloVe 用**统计式共现拟合**;应用要注意**保留词序**(RNN>平均),部署要注意**去偏**。embedding lookup 是所有 LLM 的第一层。

## Week 3 · 序列到序列模型与注意力机制(Seq2Seq & Attention)

> **本周地图**(演进笔记完全没讲,纯增量,且这是通往 Transformer 的关键一周):Encoder-Decoder 架构 → 为什么不能贪心(条件语言模型)→ Beam Search → 长度归一化 → Beam 误差分析 → BLEU 评分 → Bahdanau 注意力(Transformer 的直系祖先)。

### 3.1 Seq2Seq / Encoder-Decoder 架构

**是什么**:处理 Tx≠Ty 的任务(呼应 1.5 最后一种结构)。以机器翻译"我爱学习 → I love studying"为例:

- **Encoder(编码器)**:一个 RNN/LSTM 逐词读完源句 "我爱学习",把整句压成一个**固定长度的向量 c**(最后一步的 hidden state)。
- **Decoder(解码器)**:另一个 RNN,以 c 为初始状态,**自回归地**一个词一个词生成译文 "I love studying"(生成方式就是 1.6 的语言模型采样,只是这次以 c 为条件)。

**同构任务:图像描述(image captioning)**。把 Encoder 换成 CNN(读图片输出一个向量 c),Decoder 不变(从 c 生成一句话描述)。**这揭示了 Encoder-Decoder 的本质**:Encoder 负责"**把任意模态的输入理解成一个语义向量**",Decoder 负责"**从语义向量生成序列**"——模块可插拔。

**关键视角:Decoder 是一个"条件语言模型"**。对比 Week 1 的语言模型 P(sentence)(无条件、从零生成),Seq2Seq 的 Decoder 建模的是 **P(译文 | 源句)**——多了"以源句 c 为条件"。这个视角直接引出下一节:既然要的是概率最大的**整句译文**,该怎么找?

### 3.2 为什么不能贪心:要"最可能的句子",不是"每步最可能的词"(开篇第 5 题题眼)

**贪心搜索(greedy)**:Decoder 每一步都选当前概率最大的那个词。**看起来合理,其实错**。

**反例(Ng 的经典例子)**:翻译 "Jane visite l'Afrique en septembre"。
- 好译文:"Jane is visiting Africa in September."
- 贪心可能选:"Jane is going to be visiting Africa..." —— 因为第 3 步 "going" 的单步概率恰好比 "visiting" 高一点点,贪心就咬死了它,结果整句变啰嗦、更差。

**根本原因**:**单步最优 ≠ 全局最优**。我们要最大化的是**整句联合概率** P(y<1>,…,y<Ty> | x),而贪心用"每步的局部最优"去近似它,会在早期一个小选择上走岔、且**无法回头**。

**类比**:贪心像**爬山时每步都朝最陡的方向走**,容易卡在小山包(局部最优);找整句最优像要登**主峰**,有时得先走一段看似不那么陡的路。

**那为什么不穷举所有句子取全局最优?** 词表 1 万、句子 10 个词,就有 10000¹⁰ 种组合,天文数字,算不完。于是需要一个**折中**:比贪心看得远、又比穷举便宜——**Beam Search**。

### 3.3 Beam Search(集束搜索):在贪心和穷举之间

**核心参数:束宽 B(beam width)**。每一步不只保留 1 个最优(贪心),也不保留全部(穷举),而是**保留概率最高的 B 个部分句子(候选)**。

**流程(B=3 为例)**:

1. **第 1 步**:算 P(y<1>|x),保留概率最高的 **3 个**首词(比如 in / jane / september)。
2. **第 2 步**:对这 3 个首词,**各自**扩展所有可能的第 2 个词,得到 3×10000 个两词组合,算它们的联合概率 P(y<1>,y<2>|x)=P(y<1>|x)·P(y<2>|x,y<1>),**只留全局最高的 3 个**。
3. **重复**,每步都从"B×词表"个扩展里砍到 B 个,直到生成 `<EOS>`。

**B 的权衡(记牢)**:
- B=1 → 退化成贪心。
- B 越大 → 搜得越广、译文越好,但**计算/显存线性增加**、边际收益递减(B 从 3 到 10 提升明显,从 1000 到 3000 几乎没差)。工业上 B 常取 3~10。

> **工业锚点(直连你的推理主线)**:Beam Search 是经典机器翻译/摘要的解码主力,但现代**开放式生成 LLM(ChatGPT 类)反而很少用它**——因为 beam 倾向于挑"高概率=安全无聊"的句子,生成结果重复、乏味("beam search 退化")。开放生成改用 **采样类解码:temperature、top-k、top-p(nucleus)**(呼应 1.6 的采样),在多样性和质量间调。但翻译、代码补全这类"有明确正确答案"的任务,beam/beam 变体仍很常用。**理解 beam 的取舍,是理解 LLM 采样参数(为什么调 temperature/top-p)的地基。**

### 3.4 Beam Search 的两个 refinement（精炼） + 误差分析

**Refinement 1:长度归一化(length normalization)**。
联合概率是很多个 <1 的数**连乘**,句子越长、乘的越多、总概率越小 → beam **天生偏爱短句**(短句概率天然大)。而且连乘一堆小数会**数值下溢(underflow)**。两个问题一并解决:改成**最大化对数概率的长度归一化平均**:

```
score = (1 / Ty^α) · Σ_t log P(y<t> | x, y<1..t-1>)
```

- 取 **log**:把连乘变连加,治下溢。
- 除以 **Ty^α**(α≈0.7,经验值):抵消"长句被惩罚"的偏见。α=0 不归一化,α=1 完全按长度平均,0.7 是折中甜点。

**Refinement 2 就是上面的束宽 B 调节**(3.3 已讲)。

**误差分析(error analysis)——Ng 特别强调的工程方法论**:译文出错了,是 **Beam Search 搜得不够好**,还是 **RNN 模型本身概率估得不准**?别瞎猜,**用数据定位**:

设 y* = 人工好译文,ŷ = 模型输出的差译文。用模型算出两者的概率 P(y*|x) 和 P(ŷ|x):

| 情况 | 含义 | 该修谁 |
|---|---|---|
| **P(y*\|x) > P(ŷ\|x)** | 好译文概率明明更高,beam 却没找到它 | **Beam Search 的锅**,加大 B |
| **P(y*\|x) ≤ P(ŷ\|x)** | 模型自己就觉得差译文概率更高 | **模型(RNN)的锅**,改模型/加数据 |

在一批错例上统计"两类各占多少",就知道**该把精力投给搜索还是模型**。

> **方法论价值**:这套"**先归因、再决定优化方向**"的思维,和你做 AI Infra profiling 一模一样——延迟高了,是 compute-bound 还是 memory-bound?别凭感觉调,先用 Roofline/profiler 定位(呼应 W7 Day1/Day2)。**先测量后优化,是贯穿算法和系统的通用纪律。**

### 3.5 BLEU 评分:机器翻译怎么自动打分

**难点**:一句话有**多个正确译文**,没法像分类那样"对/错"。BLEU(Bilingual Evaluation Understudy)给一个 0~1 的自动分。

**核心:改进的 n-gram 精度(modified n-gram precision)**。
- **朴素精度**会被刷分:机器输出 "the the the the",每个 "the" 都在参考译文里出现过 → 精度 100%,但这是垃圾。
- **改进法:截断计数(clipping)**。一个 n-gram 的命中次数,**不能超过它在任一参考译文里出现的最大次数**。"the" 在参考里最多出现 2 次,那机器就算写 7 个 the,也只算命中 2 次 → 精度暴跌,刷分失败。

**综合**:算 1-gram 到 4-gram 的改进精度,几何平均;再乘一个 **简短惩罚(brevity penalty,BP)**——防止机器只输出一两个最有把握的词(短句精度虚高),句子比参考短就扣分。

```
BLEU = BP · exp( (1/4) Σ_{n=1..4} log p_n )
```

> **工业锚点 + 局限**:BLEU 是 NLP 里"**用一个可自动计算的代理指标,近似人类判断**"的开创性尝试,机器翻译评测的事实标准。但它只看 n-gram 表面重叠,**不懂语义**("好"和"棒"算不匹配)。现代 LLM 评测已转向 **语义指标(BERTScore)、模型对模型评判(LLM-as-a-judge)、人类偏好(Arena/Elo)**。但"**离线自动指标 vs 昂贵人评**"的张力——快而糙 vs 准而贵——从 BLEU 一直延续到今天你调模型时看的每一个 eval 分数。

### 3.6 Bahdanau 注意力:本课的高潮,Transformer 的直系祖先(开篇第 6 题题眼)

**Seq2Seq 的结构性瓶颈(3.1 埋的雷)**:Encoder 把**整个源句**压进**一个固定向量 c**。句子一长(50 词),这个向量就成了**信息瓶颈**——像逼你把一整篇文章浓缩成一句话再复述,长句翻译质量断崖式下跌。这正是 RNN "有损压缩"病(演进笔记 §2.1)在 Seq2Seq 上的复发。

**Bahdanau 注意力的解法(2014,神来之笔)**:**别再逼 Encoder 压成一个向量了**!保留 Encoder **每个时间步**的状态 `a<1>…a<Tx>`(每个词一个),Decoder 生成**每个**目标词时,**动态地、按需地**去"看"源句的不同部分。

**机制(直觉版)**:Decoder 生成第 i 个译词时——
1. 拿 Decoder 上一步状态 `s<i-1>`,去和 Encoder 的**每个** `a<t>` 算一个**对齐分数** `e<i,t>`(用一个小神经网络算,衡量"生成第 i 个词时该关注源句第 t 个词多少");
2. 对这些分数 softmax,得**注意力权重** `α<i,t>`(和为 1,是一组"注意力分配");
3. 用权重**加权求和** Encoder 状态,得到**为第 i 步定制的上下文向量** `c<i> = Σ_t α<i,t> · a<t>`;
4. 用这个 `c<i>` 帮助生成第 i 个译词。

**类比**:没注意力的 Seq2Seq 像**读完整篇文章、合上书、凭一句话记忆写译文**(信息瓶颈);Bahdanau 注意力像**翻译时原文摊开放在旁边,写每个词时眼睛都瞟一下原文对应的部分**——需要看哪就看哪,不用死记。翻 "Africa" 时注意力集中在源词 "l'Afrique",翻 "September" 时移到 "septembre"——这个**注意力权重矩阵可视化出来,恰好是一条软对齐的对角线**,非常直观。

**为什么它是 Transformer 的祖先(必须讲清的一句)**:
- Bahdanau:Decoder 的一个 query,去看 **Encoder 的一堆 key/value**,加权求和 → 这就是 **cross-attention(交叉注意力)** 的原型。
- Transformer 干了两件"更狠"的事:①**把 attention 从"Decoder 看 Encoder"推广到"序列看自己"**(self-attention,让源句每个词也互相看);②既然 attention 已经能让任意两个词直接交互、不再依赖 RNN 逐步传递,那**干脆把 RNN 整个删掉**,只留 attention —— 这就是 *Attention Is All You Need* 的字面意思。
- **代价的转移**:Bahdanau 的 attention 是 Decoder 步数 × Encoder 步数;Transformer 的 self-attention 是序列长度的**平方 O(n²)** → 这就接上了演进笔记 §4.3 的"账单"和 KV Cache 的故事。

> **一句话定位**:Week 3 的 Bahdanau 注意力,是"**从有损压缩(一个 c)走向无损保留(看全部 a<t>)**"的**思想转折点**;Week 4 的 Transformer,是把这个思想推到极致(删掉 RNN、self-attention 化、并行化)的**工程实现**。你手里这两篇笔记的分界线,恰好就在这里。

### Week 3 小结(一句话)

> Seq2Seq 用 **Encoder-Decoder** 处理 Tx≠Ty(Decoder = 条件语言模型 P(译文|源句));因为要**整句最优**,解码用 **Beam Search**(比贪心广、比穷举省,B 权衡质量与成本)+ **长度归一化**,出错了用**误差分析归因**(beam 还是模型的锅),质量用 **BLEU**(截断 n-gram 精度 + 简短惩罚)自动评;而 Encoder 的**单向量信息瓶颈**由 **Bahdanau 注意力**打破——它让 Decoder 动态回看源句,是 **Transformer self-attention 的直系祖先**。

>

### 4.1 动机:把注意力推到极致(承接 Week 3)

Week 3 结尾说了:Bahdanau 让 Decoder 去看 Encoder,但 **Encoder 内部还是 RNN 串行**。Transformer 的野心是——**既然 attention 这么好用,能不能连 Encoder 内部、Decoder 内部也全用 attention,把 RNN 彻底删掉?** 能。这样就摆脱了串行枷锁,整条序列并行算。

**self-attention 一句话**:让序列里**每个词直接和所有词(包括自己)交互**,不再沿时间轴逐步传递。"圆桌会议 vs 传话游戏"的类比、Q/K/V 的含义、`softmax(QKᵀ/√d)V` 的矩阵乘为什么能并行、O(n²) 的账单 —— **演进笔记 §4 全讲透了,去那读**。本周从"多头"开始补。

**Ng 课程的记法**(和演进笔记对齐,方便你对照):对每个词的 query `q<i>`,注意力输出 `A(q<i>, K, V) = Σ_t softmax(q<i>·k<t>/√d_k) · v<t>`。写成矩阵就是 `Attention(Q,K,V)=softmax(QKᵀ/√d_k)V`。

### 4.2 多头注意力(Multi-Head Attention):开篇第 8 题题眼

**单头的局限**:一次 attention 只能学**一种**"该关注谁"的模式。但语言里,一个词和其他词的关系是**多维**的——语法上它依赖谁?语义上它和谁相关?指代上它指谁?一个头顾不过来。

**多头的做法**:把 Q/K/V **各自投影成 h 份(h 个头,如 8 个)**,每份维度降到 `d_k = d_model/h`,**每个头独立做一次 attention**,最后把 h 个头的输出**拼接(concat)**,再过一个线性层 `Wo` 融合:

```
head_i = Attention(Q·Wq_i, K·Wk_i, V·Wv_i)      # 第 i 个头, 各有各的投影
MultiHead = Concat(head_1, ..., head_h) · Wo
```

**类比**:单头像**一个专家读一句话**,只带一副视角(比如只看语法);多头像**请 8 个不同专业的专家同时读**——语法专家、语义专家、指代专家…各看各的关注点,最后开会汇总(concat + Wo)。视角多元,理解更全面。

**回答开篇第 8 题"增加计算量了吗"**:**基本没有**!因为每个头的维度砍成了 1/h(`d_k=d_model/h`),h 个头加起来的总计算量,和一个 full 维度的单头**大致相当**。多头是"**在几乎不加成本的前提下,把一次大 attention 拆成多个小视角**"——花小钱办大事,这是它优雅的地方。

> **工业锚点(直连你的 KV Cache 主线!)**:多头这里藏着一个巨大的推理优化入口。标准多头,**每个头都有自己的 K、V** → KV Cache 要存 h 份,显存吃紧。于是有了:
> - **MQA(Multi-Query Attention)**:所有头**共享同一份 K、V**(只有 Q 是多头)→ KV Cache 缩小 h 倍,但质量略降。
> - **GQA(Grouped-Query Attention)**:折中,每**组**头共享一份 K、V → 现代大模型(Llama 2/3 等)的标配。
>
> 这正是演进笔记 §7 表格里"KV Cache 太占显存 → MQA/GQA"那一行的**机制来源**。你看:**多头的结构,直接决定了 KV Cache 的大小,进而决定了推理显存**——Week 4 这节和你的科研方向零距离。

### 4.3 位置编码(Positional Encoding):开篇第 7 题题眼,Transformer 的必需品

**为什么必需(承接 Week 2 §2.7 埋的线)**:self-attention 是**集合操作**——它对所有词做加权求和,**本身完全不管词的顺序**!把 "狗 咬 人" 的三个词打乱成 "人 咬 狗" 喂进去,self-attention 算出的每个词的表示**完全一样**(因为它只看两两内积,不看位置)。这就退化成了 §2.7 那个"丢词序的高级词袋"——灾难。

**对比 RNN**:RNN 天然带顺序(它就是逐步处理的,第 t 步就知道自己是第 t 个),所以**RNN 不需要位置编码**。Transformer 为了并行删掉了循环,**顺序信息也一起丢了,必须手动补回来**——这就是位置编码的使命。这一"删掉循环换并行,但要补回位置"的取舍,是理解 Transformer 的关键一环。

**怎么补:给每个位置造一个"位置向量",加到词嵌入上**。Ng 课程讲的是原论文的**正弦/余弦位置编码**:

```
PE(pos, 2i)   = sin( pos / 10000^(2i/d_model) )      # 偶数维用 sin
PE(pos, 2i+1) = cos( pos / 10000^(2i/d_model) )      # 奇数维用 cos
```

**直觉(为什么用不同频率的 sin/cos)**:类比**时钟的时针/分针/秒针**——不同维度用不同频率的波,低频维(慢针)编码"大致在句子哪段",高频维(快针)编码"精确第几个"。多个不同频率的波组合,就能给每个位置一个**唯一且平滑**的"指纹"。而且 sin/cos 有个漂亮性质:`PE(pos+k)` 能表示成 `PE(pos)` 的线性变换 → 模型容易学会"**相对位置**"(第 5 个词和第 8 个词差 3,这个"差 3"的关系在任何位置都一致)。

**位置编码怎么用**:`输入 = 词嵌入 e(word) + PE(position)`,直接相加,再送进第一层 attention。

> **工业锚点**:正弦位置编码是开山之作,但现代大模型多用**改进版**:**可学习位置嵌入**(BERT)、**RoPE(旋转位置编码)**(Llama/GPT 系主流,把位置信息编码成向量的旋转,外推长度更好)、**ALiBi**(在 attention 分数上加线性偏置)。它们都在解同一个更难的问题:**训练时最长 2k,推理时想处理 128k,位置编码怎么外推(length extrapolation)不崩**?这是长上下文 LLM 的核心工程难题之一,而它的起点就是这节的 sin/cos。

### 4.4 完整 Transformer:Encoder-Decoder 装配 + 三种 mask(深讲)

把零件拼成整机。原始 Transformer 是 **Encoder-Decoder** 结构(为翻译设计):

**Encoder(编码器,N 层堆叠)**,每层两个子层:
1. **多头 self-attention**(源句内部互相看,无 mask,可看全部);
2. **前馈网络 FFN**(position-wise,每个位置独立过同一个两层 MLP,负责非线性变换/"消化"attention 聚合来的信息)。
- 每个子层都裹上 **残差连接 + LayerNorm**(即 `LayerNorm(x + Sublayer(x))`,呼应 1.7 说的残差=梯度高速路,治深层网络的梯度问题)。

**Decoder(解码器,N 层堆叠)**,每层三个子层:
1. **带掩码的多头 self-attention**(masked,只能看已生成的词,见下);
2. **多头 cross-attention**(Query 来自 Decoder,Key/Value 来自 Encoder 输出 —— **这就是 Bahdanau 注意力的直系升级版!** Decoder 在这里"回看"源句);
3. **FFN**。
- 同样每个子层套残差 + LayerNorm。

**三种 mask(必须讲清,这是工程骨架里最易混的点)**:

| mask 类型 | 用在哪 | 干什么 | 为什么需要 |
|---|---|---|---|
| **Padding mask(填充掩码)** | Encoder & Decoder | 把 batch 里为对齐长度而填的 `<PAD>` 位置的注意力分数设为 −∞ | 一个 batch 句子长短不一,要补 PAD 对齐;但不能让真词去"注意"这些无意义的 PAD |
| **Look-ahead / causal mask(前瞻/因果掩码)** | Decoder 的 self-attention | 生成第 t 个词时,把 t 之后所有位置的注意力分数设为 −∞ | **训练时**整句并行喂入,但生成第 t 个词**不能偷看未来的词**(否则就是抄答案,推理时根本没有未来词)。因果 mask 保证"只能看过去",让训练和推理行为一致 |

> **工业锚点(因果 mask = 自回归的命根子)**:因果 mask 是 GPT 类**纯 Decoder 模型**的灵魂——它让模型只能"从左看到右",这正是自回归生成 P(下一词|前文) 的结构保证。而"训练时整句并行(有因果 mask)、推理时逐词生成(配 KV Cache 避免重算历史)"这套,就是你 W6 实现的 prefill/decode 的**理论原型** → 见演进笔记 §5.2。**因果 mask 决定了"历史 K/V 一旦算出就不再变",这正是 KV Cache 能缓存的前提**——没有因果性,就没有 KV Cache。这条因果链你要能讲出来。

**三种主流架构(收尾,建立大局观)**:
- **Encoder-only(如 BERT)**:双向看全句,擅长**理解**(分类/抽取),不能生成。
- **Decoder-only(如 GPT/Llama)**:带因果 mask,擅长**生成**,是当今大模型主流。
- **Encoder-Decoder(如原始 Transformer/T5)**:擅长**转换**类任务(翻译/摘要)。

### Week 4 小结(一句话)

> Transformer 把 Bahdanau 注意力推到极致:**删掉 RNN、全用 self-attention 并行**;为弥补丢失的顺序加**位置编码(sin/cos → RoPE)**;用**多头**在几乎不加成本下获得多元视角(且多头结构直接决定 KV Cache 大小 → MQA/GQA);用**残差+LayerNorm** 稳住深层梯度;用 **padding/causal mask** 保证正确性(**因果 mask 是自回归与 KV Cache 的前提**)。self-attention 的矩阵乘、O(n²)、KV Cache 细节 → 见演进笔记 §4-§6。

> 把 4 周拧成一句话:序列数据变长且有序 → **RNN**(参数共享 + hidden state 携带历史)能处理,但**串行慢** + **梯度消失**(门控治)/**爆炸**(裁剪治),且 one-hot 词表示零泛化 → **Week 2 词嵌入**把词换成含语义、可迁移的稠密向量(自监督 skip-gram + 负采样) → **Week 3 Seq2Seq**(Encoder-Decoder + Beam Search + BLEU)做翻译,但**单向量信息瓶颈**逼出 **Bahdanau 注意力**(动态回看,无损保留)→ **Week 4 Transformer** 把注意力推到极致(删 RNN、self-attention 并行、多头、位置编码、因果 mask),换来吞吐,代价是 **O(n²) + KV Cache 显存** → **推理优化的主战场由此注定**(FlashAttention / MQA-GQA / PagedAttention)→ 见演进笔记 §7。
